## Objetivo

Demostrar que la persistencia local implementada conserva datos, separa usuarios y protege cambios pendientes antes de añadir sincronización.

No basta con que las suites actuales pasen. Las pruebas deben ejercitar la implementación real y detectar pérdida de datos, acceso entre cuentas y sobrescrituras indebidas.

Confirma el estado real. No asumas que todas estas garantías están implementadas correctamente.

## 3. Aislamiento por usuario

Prueba con dos cuentas diferentes y acceso directo al repositorio, además de los filtros visuales.

Comprueba que la cuenta B no puede:

- Listar o consultar tareas de A.
- Editarlas, completarlas o reabrirlas.
- Eliminarlas o cambiar su estado pendiente.
- Leer, asociar o eliminar metadata de sus fotografías.
- Provocar limpieza de archivos pertenecientes a A.

Incluye intentos usando identificadores conocidos de la otra cuenta.

Verifica también que una respuesta tardía iniciada por A, después de cambiar a B, no actualice datos o estado visual de B.

Si encuentras una operación sin alcance por propietario, corrígela y añade una prueba de regresión.

## 4. Transiciones y conservación de pendientes

Inspecciona las reglas implementadas y documenta una tabla de transiciones.

Verifica, como mínimo:

- Crear offline produce `pending_create`.
- Editar una tarea `pending_create` no pierde su condición de creación pendiente.
- Editar una tarea remota limpia produce `pending_update`.
- Eliminar una tarea remota produce `pending_delete` y no aparece como activa.
- Eliminar una tarea creada exclusivamente en local no genera una eliminación remota ficticia.
- Una carga de datos remotos no sobrescribe ediciones pendientes.
- Una carga remota no resucita tareas con eliminación pendiente.
- Una respuesta vacía, parcial o fallida no borra indiscriminadamente datos locales.
- Reconectar no dispara envíos automáticos.
- Un error de almacenamiento no se presenta como guardado exitoso.
- Una respuesta remota tardía no pisa una edición local posterior.

No implementes sincronización ni resolución de conflictos para hacer pasar estas pruebas.

## 5. Resultado remoto incierto

El informe afirma que los fallos de red muestran un estado incierto. Comprueba cómo se representa realmente.

Distingue:

- Operación realizada solo localmente, sin envío remoto.
- Operación enviada cuyo resultado se desconoce porque se perdió la respuesta.
- Operación rechazada mediante HTTP explícito.

La incertidumbre debe conservarse tras reiniciar cuando sea necesaria para que P3 evite reenvíos inseguros. No basta con un mensaje transitorio en pantalla.

Prueba una mutación cuyo transporte rechaza después del intento de envío:

- Se conserva la intención y el resultado incierto.
- La interfaz no afirma éxito remoto.
- No se reenvía automáticamente.
- Reabrir SQLite conserva los metadatos necesarios.

Comprueba que errores HTTP 400, 401 o 403 no se conviertan silenciosamente en éxito local.

Si falta representación persistente de incertidumbre, implementa el cambio mínimo, con migración local segura cuando corresponda. No cambies el backend ni añadas mecanismos remotos de idempotencia en este bloque.

## 6. Acceso local y SecureStore

Usa el provider y los servicios reales, simulando SecureStore y transporte en sus límites.

Verifica:

1. Sin autenticación previa exitosa, no se habilita acceso local.
2. Una cuenta validada puede acceder únicamente a sus datos locales ante un fallo recuperable.
3. Permitir acceso local no declara válido el token remoto.
4. Un 401 explícito exige autenticación.
5. Logout revoca credenciales y habilitación local.
6. Los pendientes pueden conservarse, pero quedan inaccesibles hasta que la misma cuenta vuelva a autenticarse.
7. Otra cuenta no obtiene acceso a esos pendientes.
8. Fallos de lectura o borrado de SecureStore terminan en estados controlados.
9. Respuestas tardías de restauración, login o logout no sobrescriben ni borran credenciales de una sesión posterior.

Verifica las escrituras y borrados de SecureStore, no solo el estado final de React.

No añadas refresh tokens ni rediseñes toda la autenticación.
